> 这篇是根据学习记录整理的**概念笔记**，不是一次真实的 Qwen3-8B 训练实验。下面以因果语言模型的“预测下一个 token”为例；省略了分布式训练、混合精度等工程细节。

## 先看整条链

```text
一批文本 → 分词得到 token ID → 前向传播得到预测
        → 计算损失 → 反向传播得到梯度 → 优化器更新参数
        → 换下一批文本，重复
```

一批数据（batch）指一次送入模型的若干条训练样本。训练代码还需要处理截断、填充和哪些位置参与损失；这里只看最基本的过程。

## ① 准备输入与目标

文本先由 tokenizer 转成 token ID。因果语言模型通常让每个位置根据**当前位置及之前**的 token，预测下一个 token。可以把输入和目标理解为错开一位：

```text
位置输入：  [A, B, C]
预测目标：  [B, C, D]
```

这只是示意，真实数据里的特殊 token、填充位等需要单独处理。“首都”这样的词在具体 tokenizer 中**不一定对应一个 token**；若拆成多个 token，就分别在相应位置计算预测损失。因果注意力会遮住未来位置，训练时虽然可同时计算许多位置，当前位置仍不能偷看后面的答案。

## ② 前向传播：先得到预测

每个 token ID 先变成向量，再逐层经过 Transformer，最终在每个位置输出对词表的预测分数（logits）；把分数转成概率后，才能讨论正确 token 的概率。这里选 Qwen3-8B 作例子：官方配置写有 **36 个 Transformer 层**。这不是说每个 token 在训练时都要按生成顺序一个接一个地跑完所有层；因果掩码允许一批已知训练文本的多个位置并行计算。有关层内部的注意力与前馈网络，另见[《Transformer 层：注意力与前馈网络》](../transformer-layer/)。

## ③ 计算损失：把预测差距变成数字

若某位置的目标 token 是 `y`，模型分给它的概率为 `P(y)`，该位置的负对数似然可写为：

```text
loss = -log P(y)
```

目标 token 的概率越低，损失越高。训练时通常把 batch 中**参与训练的位置**的损失汇总或求平均，而不是只看某一个字词。实现上常用交叉熵损失；被忽略的位置不应计入平均。

## ④ 反向传播与参数更新

反向传播求出损失对**可训练参数**的梯度；优化器再依据梯度和自己的更新规则修改参数。一个简化的步骤是：

```text
清空旧梯度 → 前向传播 → 计算损失 → backward 求梯度 → optimizer.step 更新参数
```

这有一个重要区别：**反向传播负责算梯度，`optimizer.step()` 才实际更新参数**。不能保证更新后某一个例子里“首都”的概率必然上升，因为更新依据是整批样本的目标，而且学习率和优化器状态也有影响。

上面假设一个 batch 对应一次优化器更新。使用**梯度累积**时，可能先对多个 micro-batch 求梯度，再统一更新一次。

## ⑤ 换下一批，反复训练

更新完参数，继续取下一批文本。**训练**包含损失、梯度与参数更新；普通的**推理**只利用当前参数做前向计算和生成，不会因为回答了一次问题就自动修改参数。

## 复盘与资料

- 要分清三个动作：模型预测、反向计算梯度、优化器更新参数。
- “预测下一个 token”的目标是在**每个有效位置**上定义的，不等于一次只训练一个 token。
- 本文没有记录真实训练的 batch size、损失曲线或硬件配置，因此不构成实验结果。
